## 2025-02-28 - Optimizing fairnessEngine/aimingWorker crypto
**Learning:** The continuous string allocation and hex parsing for floating point generation (`hash.slice(0, 8)` to `parseInt`) is a significant bottleneck, particularly in tight inner loops like `aimingWorker.ts` brute-forcing. Using `CryptoJS.algo.HMAC.create` to cache the context and using bitwise shifts (`hash.words[0] >>> 0`) rather than intermediate `.toString(CryptoJS.enc.Hex)` strings provides over a 2.5x speedup for floating point conversion. Same caching technique accelerates Crash verification significantly by operating on the `words` directly.
**Action:** Replace `HmacSHA256` string generation and subsequent slicing/parsing with direct cached `HMAC` operations and bitwise manipulation for hot crypto paths.
