## 2024-05-23 - crypto-js HMAC allocation and hot path optimization
**Learning:** `crypto-js` is highly allocation-heavy when creating new `HmacSHA256` instances and calling `.toString(CryptoJS.enc.Hex)`. By caching the HMAC instance using `CryptoJS.algo.HMAC.create` and `.reset()`, and avoiding Hex conversions by accessing the 32-bit floats directly from `hash.words[0] >>> 0`, synchronous hot paths can be sped up significantly (~2.5x speedup). This is extremely critical for performance-sensitive loops running brute force hashing algorithms, like `aimingWorker`.
**Action:** When working with repetitive hashing loops in TS/JS applications using `crypto-js`, always cache and reuse instances with `reset()` instead of creating new instances. Retrieve raw numeric data via the `words` array where feasible instead of expensive string conversion mechanisms.
