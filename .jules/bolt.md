## 2024-05-24 - crypto-js performance hot paths
**Learning:** Using `crypto-js` with hex string conversions (`.toString(CryptoJS.enc.Hex)`) and parsing (`parseInt()`) creates massive overhead in high-frequency cryptographic hash operations, like generating thousands of deterministic floats or 52-bit integers during iterative fairness testing.
**Action:** When optimizing synchronous hot paths using `crypto-js`, cache the HMAC instance via `CryptoJS.algo.HMAC.create` and reuse it using `.reset()` and `.update()`. Furthermore, extract values directly via bitwise shifts on the `.words` array (e.g. `(hash.words[0] >>> 0) / 4294967296` for 32-bit floats, and `(hash.words[0] >>> 0) * 1048576 + (hash.words[1] >>> 12)` for 52-bit crash integers) rather than using `.toString(CryptoJS.enc.Hex)` and `parseInt()`.
