## 2024-05-29 - [HMAC Float Generation Cache]
**Learning:** In the hot path of CSPRNG deterministic float generation (`generateFloat` in `fairnessEngine.ts` and `aimingWorker.ts`), creating a new `CryptoJS.algo.HMAC.create` instance for every single float calculation is a significant bottleneck. This is because these routines are called millions of times during brute-force Monte Carlo simulations.
**Action:** When optimizing synchronous hot paths using `crypto-js`, cache the HMAC instance via `CryptoJS.algo.HMAC.create` and reuse it using `.reset()` and `.update()`. Access the `words` array directly with bitwise shifts (e.g., `hash.words[0] >>> 0`) rather than converting to a hex string with `.toString(CryptoJS.enc.Hex)` and parsing it. Implement a single-value cache (e.g., tracking `lastSeed` and `lastHmac`) rather than unbounded Maps to prevent memory leaks.
