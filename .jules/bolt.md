## 2023-10-24 - [Optimize Hot Path `generateFloat` and HMAC creation]
**Learning:** In synchronous hot paths using `crypto-js`, repeatedly creating HMAC-SHA256 instances via `CryptoJS.HmacSHA256` adds massive overhead. Instantiating via `CryptoJS.algo.HMAC.create` and reusing via `.reset()` and `.update()` dramatically improves performance (e.g. 742ms vs 1993ms in benchmark, almost ~60% reduction in time). Furthermore, `.toString(CryptoJS.enc.Hex)` adds allocation and slicing overhead compared to extracting the 32-bit float directly via `.words[0] >>> 0`. We must also cache the HMAC based on the serverSeed.
**Action:** When calculating cryptographic floats in hot loops, use `CryptoJS.algo.HMAC.create` mapped to `serverSeed`, utilize `.reset()`/`.update()`, and extract words via bitwise operators rather than converting to a hex string first. Apply this to `fairnessEngine.ts` and `aimingWorker.ts`.
