## 2024-04-17 - Direct CryptoJS bitwise extraction
**Learning:** `CryptoJS` stringification and parsing inside hot-path cryptographic fairness generators (like converting HMAC values to floats or 52-bit Crash integers) is a massive performance bottleneck. Because CryptoJS internally stores hashes as an array of 32-bit integers (`hash.words`), converting to a hex string (`.toString()`), slicing the string, and parsing it back with `parseInt()` is entirely redundant.
**Action:** When working with CryptoJS output that ultimately needs to be a number, bypass string manipulation entirely. Extract exactly what is needed using bitwise shifts (e.g. `(hash.words[0] >>> 0)` for a 32-bit unsigned int). For larger safe integers up to 53 bits (like Crash's 52-bit integer), combine multiple words safely: `(hash.words[0] >>> 0) * 1048576 + (hash.words[1] >>> 12)`. This reduces execution time by over 50%.
