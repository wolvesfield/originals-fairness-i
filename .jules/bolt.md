## 2024-05-20 - HMAC caching and array pre-allocation for high-frequency cryptography
**Learning:** Instantiating `CryptoJS.algo.HMAC.create` and converting the result using `.toString(CryptoJS.enc.Hex)` combined with `parseInt()` is highly inefficient inside tight, ultra-high-frequency loops because of excessive string parsing, hexadecimal transformation overhead, and unnecessary garbage collection. Further, dynamically sized structures like `Set` and `Array.from` cause continuous memory allocations that severely degrade throughput compared to using pre-allocated TypedArrays (`Int32Array`, `Uint8Array`).
**Action:** For hot cryptographic loops, reuse a persistent or LRU-cached `CryptoJS.algo.HMAC.create` instance using `reset()` and `update()`, and access the computed `hashObj.words` directly via bitwise shifts (e.g., `hash.words[0] >>> 0`) for rapid number extraction. Use globally pre-allocated TypedArrays to track state (like collision detection) rather than allocating `new Set()` inside the loop.
