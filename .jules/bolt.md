## 2025-03-05 - Optimize CryptoJS HMAC hot paths
**Learning:** In synchronous hot paths like `generateFloat` which is called thousands of times per second (e.g. Monte Carlo simulations or brute-forcing), repeatedly calling `CryptoJS.HmacSHA256` and allocating strings via `.toString(CryptoJS.enc.Hex)` is a major bottleneck. The optimal pattern is to cache a single HMAC instance via `CryptoJS.algo.HMAC.create` and reuse it using `.reset()`, `.update()`, and `.finalize()`. Extracting the float directly from `hash.words[0] >>> 0` avoids string parsing overhead, speeding up generation by ~2.7x.
**Action:** When using `crypto-js` in tight loops, always cache the HMAC instance, use a single-value cache (e.g. `lastSeed`, `lastHmac`) to avoid memory leaks, and extract values using bitwise operations on the `words` array rather than string encoding/decoding.
