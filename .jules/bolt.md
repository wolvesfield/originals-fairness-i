## 2024-05-18 - CryptoJS HMAC instance memory allocation & extraction optimization
**Learning:** Instantiating new CryptoJS HMAC objects for every single float generation creates significant garbage collection overhead and memory leak risks in high-frequency processes. Additionally, converting the final hash to a hex string (`toString(CryptoJS.enc.Hex)`) and then parsing it via `parseInt(slice, 16)` is an expensive transformation.
**Action:** Use a Bounded LRU Cache (e.g. `Map` with `.size` checks) to reuse `CryptoJS.algo.HMAC.create()` instances via `.reset()` and `.update()`. Instead of hex parsing, directly extract the first 4 bytes using the internal `words` array (`hash.words[0] >>> 0`) to cast it to an unsigned 32-bit integer for a massive speedup in math generation loops.
