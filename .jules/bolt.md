## 2024-05-18 - Hot-Path Cryptography Optimization
**Learning:** In highly repetitive cryptographic validation loops (like brute-forcing or Monte Carlo simulations in `fairnessEngine.ts` and `aimingWorker.ts`), relying on `CryptoJS.HmacSHA256().toString(CryptoJS.enc.Hex)` and parsing it back with `parseInt` is a significant performance bottleneck due to continuous string allocation and hash instance recreation. Additionally, instantiating `Set`s for collision detection inside tight loops adds substantial GC pressure.
**Action:** When optimizing synchronous hot paths using `crypto-js`, cache the HMAC instance via `CryptoJS.algo.HMAC.create` and reuse it using `.reset()` and `.update()`. Access the `words` array directly with bitwise shifts (e.g., `hash.words[0] >>> 0`) rather than converting to a hex string. For collision detection in small domains (like Keno 1-40), replace `Set` with pre-allocated `Uint8Array`s and early loop exits.
