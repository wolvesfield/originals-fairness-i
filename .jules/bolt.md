## 2024-05-18 - CryptoJS HMAC caching and extraction optimization
**Learning:** For deterministic float and hash generation using `crypto-js`, relying on `CryptoJS.HmacSHA256().toString(CryptoJS.enc.Hex)` combined with `parseInt(hash.slice(0, 8), 16)` is inefficient in hot loops. The hex string conversion and parsing alone takes substantial time. Using `CryptoJS.algo.HMAC.create()` to reuse instances via `.reset()` and `.update()` improves performance. Furthermore, accessing the internal 32-bit words array directly (`hash.words[0] >>> 0`) rather than converting to a hex string and back to a number provides massive performance improvements, turning ~4.1s execution into ~1.6s for 100k float generations. Using Node's native `crypto` is even faster but not compatible with browser-native Web Workers without a polyfill. The Web Crypto API (`crypto.subtle`) could be used, but since it's asynchronous, it breaks synchronous code paths like `.map` or `for` loops expecting an immediate float. Therefore, caching `CryptoJS` HMAC and direct bitwise extraction is the best synchronous approach.
**Action:** When optimizing synchronous hot paths using `crypto-js`, cache the HMAC instance via `CryptoJS.algo.HMAC.create` and reuse it using `.reset()` and `.update()`. Access the `words` array directly with bitwise shifts (e.g., `(hash.words[0] >>> 0) / 4294967296`) rather than converting to a hex string with `.toString(CryptoJS.enc.Hex)`.
