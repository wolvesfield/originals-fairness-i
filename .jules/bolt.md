## 2024-05-24 - CryptoJS HMAC-SHA256 Float Generation Bottleneck
**Learning:** In tight loops like nonce scanning (e.g. `aimingWorker.ts`) or large scale simulations, re-instantiating `CryptoJS.HmacSHA256` and subsequently converting the result to a hex string via `toString(CryptoJS.enc.Hex)` just to extract the first 4 bytes is a massive bottleneck. Generating a float this way takes ~400ms per 10k ops. Caching the HMAC object via `CryptoJS.algo.HMAC.create` and accessing the hash words directly (`hash.words[0] >>> 0`) bypasses string allocation entirely and reduces time to ~150ms per 10k ops (a 2.5x speedup).
**Action:** When optimizing synchronous hot paths using `crypto-js`, cache the HMAC instance via `CryptoJS.algo.HMAC.create` and access the `words` array directly with bitwise shifts (e.g., `hash.words[0] >>> 0`) rather than converting to a hex string with `.toString(CryptoJS.enc.Hex)` to significantly improve performance.
